Phase 1 shipped

Tennon

The Kubernetes-native control plane and proxy for Model Context Protocol (MCP) servers. Register an MCP server once, and every agent calls its tools through one URL — with the server's credential injected server-side and never handed to the caller.

What's built today

Phase 1 of the roadmap is implemented and verified end-to-end: register a connector, reconcile it, and proxy its tools at /mcp/<name> using the connector's rendered credential — never exposing that credential to the caller.

🔌 Per-connector MCP proxy

Every connector is reachable at /mcp/<name> over MCP streamable-HTTP. An agent points a standard MCP client straight at the URL — no sidecar, no npm package.

🔐 Credentials stay put

Header/env values carry {{secret:name.key}} templates, rendered in-process at call time and injected into the upstream. The caller sends no token and never sees one.

🧰 Tool prefixing & filtering

Upstream tools are re-exposed with a configurable exposePrefix and scoped by allow/deny globs — deny wins over allow.

♻️ Controller reconcile loop

A store-driven controller watches connectors, drives the data plane, discovers tools, and writes back status.phase / discoveredTools / url.

🗄️ Pluggable storage

In-memory and SQLite backends today, behind one domain.Store port with get / list / watch semantics — same objects on every backend.

🖥️ One binary + CLI + API

The tennon server (controller + API + proxy + embedded UI) and the tctl CLI, wired at a single Uber-FX composition root. REST API; secret data is write-only.

In Phase 1, step 1 resolves to a local subject and step 2 is an allow-all default — both sit behind ports (IdentityVerifier, Authorizer) so real OIDC (Phase 2) and Cedar-compiled policy (Phase 3) drop in without changing the proxy.

Architecture — packages only call down

cmd/  cmd/tennon (FX composition root), cmd/tctl
delivery  api · proxy · controller · cli
infrastructure  store · runtime · secret · auth
domain  core types + port interfaces — imports nothing outward

The dependency rule: a package may import only packages in a lower layer. domain is pure Go (stdlib only); when a lower layer needs upward behaviour it defines an interface the higher layer implements (e.g. the controller drives the proxy through domain.Router). Enforced by hack/check-layers.sh in task check.

Run it yourself

1 · Build

# builds ./bin/tennon and ./bin/tctl
task build

2 · Start a mock MCP upstream (to try the flow)

go run ./hack/mockmcp --addr 127.0.0.1:9090

3 · Run the control plane (solo / local, in-memory store)

./bin/tennon --store memory --runtime remote \
  --api-addr 127.0.0.1:8080 --proxy-addr 127.0.0.1:8081

4 · Register a credentialed connector

# the credential lives with the connector — callers never receive it
export TENNON_API=http://127.0.0.1:8080
./bin/tctl secret create grafana-creds --from-literal token=$GRAFANA_TOKEN
./bin/tctl connector add grafana \
  --remote http://127.0.0.1:9090/mcp \
  --header "Authorization=Bearer {{secret:grafana-creds.token}}" \
  --expose-prefix grafana_ --allow "get_*" --tag observability
./bin/tctl connector list
#  grafana   remote   Ready   /mcp/grafana

An agent then points its MCP client at http://127.0.0.1:8081/mcp/grafana. The proxy injects the connector's credential server-side, so the agent holds no secret. For persistence, swap --store sqlite --store-path tennon.db.

Roadmap  Not yet built

Phase 1.1 — Spec connectors

Compile tools in-process from an OpenAPI spec (OpenApiConnector) or GraphQL endpoint (GraphqlConnector); OAuthApp + minted token (Google as the proof).

Phase 2 — Storage & authentication

Postgres and Kubernetes/etcd backends; OIDC login (Google, Okta); service tokens; secret rendering from references.

Phase 3 — Authorization

Policy CRD compiled to Cedar, evaluated in-process; additive, most-restrictive-wins; allow / ask / block, live-reloaded.

Phase 4 — Tokenless identity & catalog

Trust-based machine identity (K8s ServiceAccount, SPIFFE, OIDC JWT, cloud); fine-grained tokens; unified tool catalog with intent search.

Phase 5 — Approvals & web UI

Pause/resume executions (human-in-the-loop); the click-driven Vite/React console; the CLI's embedded MCP server for programmatic agent access.

Runtime backends

Kubernetes Pods with runtimeClass / NetworkPolicy / KubeArmor isolation; the stdio→streamable-HTTP bridge (Supergateway). Docker runtime exists but is lightly exercised.

Tennon is pre-1.0 and under active design; APIs and CRD schemas may change. This page describes only code that exists in the repository as of Phase 1. Full documentation lives under docs/.
